W1 · LEARNING 01

采购申请、采购订单与收货入库

HYT-M1-W1-L01

学习目标

能够理解采购业务从申请到收货的业务事实、系统记录和会计影响，并识别关键系统控制。

核心内容

  • 采购申请表示内部采购需求，通常不直接形成会计记录，但可作为采购授权控制的起点。
  • 采购订单记录供应商、物料、数量、价格、交期等关键交易条件，是后续收货和发票匹配的重要基础。
  • 收货/入库表示企业已经取得货物或控制权，是存货数量增加和暂估应付判断的重要业务事实。
  • 采购订单、收货单、入库单可能由ERP、SRM、WMS等不同系统生成，需要确认哪个系统是原始数据源。
  • 采购订单价格、供应商、收货数量等字段如果可被未授权修改，可能影响存货、成本和应付。
  • 三单匹配、采购限价、供应商状态校验等常见ITAC通常位于采购流程中。

判断与执行步骤

  1. 确认采购申请、订单、收货分别由哪个系统处理。
  2. 确认采购订单和入库单的关键字段及修改权限。
  3. 明确收货后是否自动生成入库、暂估或会计凭证。
  4. 识别订单、收货和发票之间的匹配逻辑。
  5. 将异常分别映射到存货、应付、成本等科目。
  6. 确定需要验证的ITAC、接口或IPE。

常用资料 / 审计证据

  • 采购申请、采购订单、收货单、入库单。
  • 供应商主数据、采购价格表。
  • 三单匹配或收货控制配置。
  • 采购订单修改日志。
  • ERP/WMS接口记录。

应用场景

采购订单为100件，WMS实际收货100件，但ERP只形成80件入库。需要判断是接口漏传、人工处理还是业务差异，并分析对存货及应付暂估的影响。

完成后应能回答

  • 采购订单和收货单分别证明什么业务事实？
  • 为什么WMS库存数量正确不代表ERP会计记录一定正确？
  • 采购数量、采购价格和供应商主数据分别可能影响哪些财务结果？

W1 · LEARNING 02

暂估、发票与应付账款

HYT-M1-W1-L02

学习目标

能够理解货物已收但发票未到时的暂估逻辑，以及发票到达后的冲回和应付确认。

核心内容

  • 制造企业常见“货到票未到”，企业可能根据入库或收货记录确认暂估应付。
  • 暂估金额可能来自采购订单价格、标准价格、最近采购价格等，需要理解实际规则。
  • 发票到达后系统可能自动冲回暂估并按发票金额形成正式应付。
  • 如果暂估未完整生成，可能造成存货/成本已确认但应付少记。
  • 如果暂估未正确冲回，可能产生重复负债或成本。
  • 期末未开票收货清单、暂估明细、发票匹配表通常属于关键IPE。

判断与执行步骤

  1. 确认企业暂估触发条件和计算依据。
  2. 确认暂估金额从哪里取值。
  3. 确认发票到达后的匹配和冲回逻辑。
  4. 核对期末收货未开票总体。
  5. 检查跨期发票和冲回。
  6. 判断完整性、准确性和截止影响。

常用资料 / 审计证据

  • 期末收货未开票清单。
  • 暂估应付明细。
  • 供应商发票。
  • 采购订单和入库记录。
  • 暂估生成/冲回配置或程序说明。

应用场景

12月28日已入库材料，供应商1月5日开票。ERP根据入库单自动暂估。需要判断暂估是否完整、金额来源是否合理、1月正式发票是否正确冲回。

完成后应能回答

  • 为什么期末暂估主要关系到负债完整性和存货/成本截止？
  • 暂估金额与正式发票金额不一致时系统应如何处理？
  • 哪些系统报表可用于检查期末暂估完整性？

W1 · LEARNING 03

库存数量、库存状态与盘点

HYT-M1-W1-L03

学习目标

能够区分账面库存数量、仓库实物数量和不同库存状态，并理解库存数量数据对财务报表的影响。

核心内容

  • WMS通常记录仓库实物移动和库存数量；ERP可能同时记录数量和金额。
  • 库存可能分为可用、冻结、在途、质检、寄售、残次、委外等状态，不同状态的会计处理可能不同。
  • 盘点差异需要经过盘盈盘亏审批和账务调整，不能只看最终库存余额。
  • 负库存、长期无移动库存和异常调拨可能提示业务或系统问题。
  • 库存数量错误会直接影响存货存在/完整性，也可能影响成本结转。
  • 系统库存报表作为财审盘点或存货测试依据时，需要验证IPE完整性和准确性。

判断与执行步骤

  1. 确认WMS与ERP分别保存什么库存信息。
  2. 理解库存状态字段及业务含义。
  3. 确认收发存和调拨如何改变库存。
  4. 确认盘点差异如何审批和入账。
  5. 核对WMS与ERP数量差异。
  6. 将数量异常连接到存货认定和成本影响。

常用资料 / 审计证据

  • WMS库存明细、ERP库存台账。
  • 盘点表、盘盈盘亏单。
  • 库存状态字段说明。
  • 调拨、冻结、报废记录。
  • WMS→ERP库存接口日志。

应用场景

WMS显示仓库有1,000件，其中200件处于冻结状态；ERP总库存也为1,000件。需要确认冻结库存是否仍属于企业、是否可正常销售及是否存在减值影响。

完成后应能回答

  • 库存状态为什么会影响财审判断？
  • WMS与ERP数量一致是否就可以证明存货可靠？
  • 盘点差异如何追到最终会计调整？

W1 · LEARNING 04

生产领料、完工入库与在制品

HYT-M1-W1-L04

学习目标

能够理解制造业务中材料如何从原材料转入生产成本、在制品和产成品。

核心内容

  • 生产订单/工单用于记录生产任务、物料、数量、工艺和计划。
  • 领料会减少原材料库存，并进入生产成本或在制品。
  • 完工入库会增加产成品，并将对应生产成本从在制品转入产成品。
  • 材料消耗可能按实际领料、BOM标准或倒冲方式记录，需要确认企业采用的模式。
  • MES、WMS和ERP之间可能存在生产数据接口。
  • 工单数量、材料耗用、工时、完工数量等数据错误会影响存货和成本。

判断与执行步骤

  1. 确认工单由哪个系统产生。
  2. 确认领料、退料、补料和完工如何记录。
  3. 确认材料消耗采用实际领料还是倒冲。
  4. 确认MES/WMS数据如何进入ERP。
  5. 确认在制品和产成品成本何时结转。
  6. 识别可能影响数量、成本和截止的异常。

常用资料 / 审计证据

  • 生产工单、BOM。
  • 领料单、退料单、完工入库单。
  • MES生产记录。
  • WMS库存移动。
  • ERP生产成本/在制品明细。

应用场景

MES显示某工单完工1,000件，ERP只收到900件完工入库；材料已经按1,000件耗用。需要分析接口和人工调整，并判断在制品、产成品和成本的影响。

完成后应能回答

  • 为什么制造业IT审计需要同时看MES、WMS和ERP？
  • 倒冲领料与实际领料有什么数据风险差异？
  • 完工数量异常会影响哪些科目？

W1 · LEARNING 05

成本归集、分配与结转

HYT-M1-W1-L05

学习目标

能够理解材料、人工、制造费用如何进入产品成本，以及自动成本计算为什么可能构成关键ITAC。

核心内容

  • 产品成本通常由直接材料、直接人工和制造费用组成。
  • 制造费用需要通过工时、机时、产量或其他分配基础分摊。
  • 企业可能采用标准成本、移动平均、月末加权平均、实际成本等方法。
  • 成本计算依赖物料价格、领料数量、工时、完工数量、分配参数等输入。
  • ERP自动成本计算通常包含参数、公式、取数范围和结转规则。
  • 成本错误不仅影响存货，也会影响营业成本和利润。

判断与执行步骤

  1. 确认成本方法和会计政策。
  2. 识别成本计算输入。
  3. 识别系统参数和公式。
  4. 确认计算触发时点和期间。
  5. 选择样本重算并与系统结果比较。
  6. 分析异常对存货计价和营业成本的影响。

常用资料 / 审计证据

  • 成本计算配置。
  • 物料价格和采购成本。
  • 领料/完工数据。
  • 工时、机时、制造费用。
  • 成本计算表和结转凭证。

应用场景

ERP月末自动计算加权平均成本，并据此更新存货和结转营业成本。该控制需要验证取数范围、计算公式、异常处理和相关ITGC。

完成后应能回答

  • 自动成本计算为什么可能是ITAC？
  • 成本计算的关键输入有哪些？
  • 成本计算错误为什么会同时影响资产负债表和利润表？

W1 · LEARNING 06

销售、发货、收入与应收

HYT-M1-W1-L06

学习目标

能够把销售业务从订单到发货、收入确认、应收和回款串起来，并应用财务报表认定。

核心内容

  • 销售流程通常包括报价/订单、信用或价格审批、发货、签收、开票、收入确认、应收和回款。
  • 制造企业可能由ERP销售模块生成订单，WMS负责发货，财务系统自动记账。
  • 收入确认时点应结合履约条件，不能简单等同于开票时点。
  • 发货数量、销售价格、折扣、客户和确认日期都是关键字段。
  • 常见ITAC包括信用额度、最低售价、折扣审批、自动收入确认。
  • 常见财务风险包括虚构收入、漏记收入、错误价格、提前确认和跨期。

判断与执行步骤

  1. 确认收入确认政策。
  2. 画出销售订单到会计凭证的系统链。
  3. 确认发货和签收数据来源。
  4. 确认价格、折扣和信用控制。
  5. 确认自动收入确认逻辑。
  6. 将异常映射到收入、应收、成本和相关认定。

常用资料 / 审计证据

  • 销售订单、发货单、签收记录。
  • 价格表、折扣配置。
  • ERP收入明细、应收明细。
  • WMS发货明细。
  • 回款和核销记录。

应用场景

12月31日ERP根据WMS“已出库”状态自动确认收入，但部分货物实际1月2日才离开仓库。需要重点分析收入发生和截止。

完成后应能回答

  • 为什么系统状态需要和真实业务事实核对？
  • 销售价格异常主要影响什么认定？
  • 收入接口遗漏和提前发货状态分别可能造成什么错报？

W2 · LEARNING 01

ITAC的基本结构与财审目的

HYT-M1-W2-L01

学习目标

能够识别一个控制是否属于ITAC，并用完整结构描述其风险、逻辑和财审意义。

核心内容

  • ITAC是由应用系统自动执行或高度依赖系统逻辑的控制。
  • 常见类型包括自动计算、自动校验/限制、自动工作流、自动匹配、自动记账。
  • ITAC的价值在于重复、稳定地处理大量交易，但前提是逻辑、配置、输入和系统环境可靠。
  • 识别ITAC时要先明确它应对的业务或财务报告风险。
  • 财审是否依赖ITAC取决于该控制是否与重大账户或重大错报风险相关。
  • ITAC测试结论需要与相关ITGC、主数据、接口或IPE一起考虑。

判断与执行步骤

  1. 先描述业务风险。
  2. 明确控制触发条件。
  3. 识别系统逻辑和关键参数。
  4. 确认输入和主数据。
  5. 确认系统输出和例外。
  6. 说明控制对应的财务报表认定和财审依赖。

常用资料 / 审计证据

  • 业务流程和控制矩阵。
  • 系统配置和控制说明。
  • 参数、主数据。
  • 历史交易或测试交易。
  • 财审风险/认定清单。

应用场景

ERP在销售订单审核时自动检查客户信用额度，超额订单不能继续。该控制可能用于降低信用风险，但测试前还需确认其是否与财审依赖相关。

完成后应能回答

  • 什么条件下一个系统功能可以称为ITAC？
  • 为什么ITAC不能只看功能截图？
  • 财审目的和系统功能描述有什么区别？

W2 · LEARNING 02

自动计算类ITAC

HYT-M1-W2-L02

学习目标

能够拆解成本、折旧、利息、汇率、税额等自动计算控制的输入、公式、参数和输出。

核心内容

  • 自动计算的核心是“输入 × 逻辑/公式 × 参数 = 输出”。

W4 · LEARNING 01

HR × 账号 × 登录日志

HYT-M1-W4-L01

学习目标

能够用人员、账号和日志三类数据验证离职停用、无效账号和实际使用风险。

核心内容

  • HR数据提供人员状态和离职日期。
  • 账号清单提供用户ID、启停状态、角色和最后登录等信息。
  • 登录/操作日志提供账号是否在离职后实际使用的证据。
  • 三类数据需要确定可靠关联键，例如工号、邮箱、账号ID。
  • 账号仍Active与账号实际被使用是两个不同风险层级。
  • 异常应根据高权限、实际登录、关键操作进一步分层。

判断与执行步骤

  1. 明确审计问题。
  2. 验证三个数据源的期间和完整性。
  3. 建立人员与账号映射。
  4. 筛选离职后仍Active。
  5. 关联离职后登录和操作。
  6. 按权限和操作风险分层。
  7. 抽样核验并形成结论。

常用资料 / 审计证据

  • HR员工主数据。
  • 系统账号清单。
  • 角色/权限清单。
  • 登录日志。
  • 关键操作日志。

应用场景

42个离职人员账号仍Active，其中8个离职后有登录，2个拥有高权限。核验重点应进一步集中到实际登录和高权限操作。

完成后应能回答

  • 为什么Active账号数量不能直接等于问题严重程度？
  • 人员和账号关联键不可靠时怎么办？
  • 哪些操作日志会显著提高风险等级？

W4 · LEARNING 03

WMS × ERP × 盘点/业务单据

HYT-M1-W4-L03

学习目标

能够用仓库、财务和实物/业务证据验证库存异常，避免只依赖单一系统。

核心内容

  • WMS通常更接近实物移动，ERP用于会计记录和计价。
  • 两套系统差异可能来自接口时间差、手工调整、状态口径或真正漏传。
  • 盘点结果可以提供第三类独立证据。
  • 异常调拨、负库存、冻结库存等需要结合业务单据。
  • 数量差异需要继续判断是否影响金额和成本。
  • 跨系统一致不代表实物一定存在，因此必要时要结合盘点或物流证据。

判断与执行步骤

  1. 核对两个系统库存总体。
  2. 按物料/仓库/日期分层差异。
  3. 识别接口和时间差。
  4. 检查调整/调拨。
  5. 结合盘点或业务单据。
  6. 量化财务影响。

常用资料 / 审计证据

  • WMS库存。
  • ERP库存。
  • 盘点表。
  • 调拨/调整单。
  • 接口日志。

应用场景

ERP和WMS均显示某物料1,000件，但盘点只有800件。两系统一致仍不能说明存货存在认定可靠。

W4 · LEARNING 04

异常分层与优先级

HYT-M1-W4-L04

学习目标

能够根据权限、金额、频率、期间和财务影响对异常进行分层，优先核验高风险事项。

核心内容

  • 数据分析通常产生大量异常，不应平均投入时间。
  • 权限异常可按普通用户、高权限、实际操作进一步分层。
  • 交易异常可按金额、月末、关联方、手工调整等维度分层。
  • 接口异常可按未落地金额、是否跨期、是否影响重大科目分层。
  • 分层标准应与审计风险相关，不只是数据分布。
  • 异常分层后选择高风险记录详查，其他记录可抽样或汇总。

判断与执行步骤

  1. 列出异常总体。
  2. 选择与审计风险相关的分层字段。
  3. 建立高/中/低风险规则。
  4. 优先检查高风险。
  5. 抽样中低风险。
  6. 记录剩余总体和残余风险。

常用资料 / 审计证据

  • 异常清单。
  • 金额字段。
  • 用户权限。
  • 业务日期。
  • 财审重大科目信息。

应用场景

月末有212笔销售出库反审核，其中45笔数量变化、11笔未重新审核。优先级应重点考虑未重审、金额、月末截止和最终财务记录。

完成后应能回答

  • 为什么异常数量多不代表风险一定高？
  • 哪些字段最适合做第一轮分层？
  • 如何避免对低风险记录无限深挖？

W4 · LEARNING 05

证据链与异常定性

HYT-M1-W4-L05

学习目标

能够用多来源证据形成事实、控制要求、业务结果和财务影响的完整判断。

核心内容

  • 第一层是事实：谁、何时、在哪个系统、做了什么。
  • 第二层是控制要求：制度、系统规则或审批要求。
  • 第三层是验证证据：日志、主数据、业务单据、财务数据。
  • 第四层是业务结果：交易是否真正发生或被修改。
  • 第五层是财务影响：是否造成金额、期间、科目或披露变化。
  • 结论要区分资料不足、个别例外、执行偏差和设计缺陷。

判断与执行步骤

  1. 写一句异常事实。
  2. 列控制要求。
  3. 整理多来源证据。
  4. 追踪业务结果。
  5. 追踪财务结果。
  6. 识别证据缺口。
  7. 形成有边界的结论。

常用资料 / 审计证据

  • 制度。
  • 系统日志。
  • 业务单据。
  • 会计凭证。
  • 补偿控制证据。

应用场景

12月31日销售出库单反审核后数量从100改为60，再重新审核。需要追发货、收入、成本和凭证历史，而不能只停在“发生反审核”。

完成后应能回答

  • 技术操作如何追到业务和会计结果？
  • 资料不足和执行缺陷如何区分？
  • 什么情况下需要测试补偿控制？

W4 · LEARNING 06

交叉验证的调查边界与结论

HYT-M1-W4-L06

学习目标

能够在取得足够证据支持审计目的后停止扩展，保证分析服务于项目结论。

核心内容

  • 开始分析前必须明确审计问题和需要回答的结论。
  • 每增加一个数据源都应说明它解决什么证据缺口。
  • 如果新增分析不会改变结论、财务影响或风险等级，应考虑停止。
  • 低风险异常可以记录总体特征，不需要逐笔无限核查。
  • 重大异常需要确定金额、范围、期间和相关控制影响。
  • 最终底稿应保留方法、总体、规则、异常、核验和结论，而不是只留代码或明细。

判断与执行步骤

  1. 定义问题和停止条件。
  2. 确定最小必要数据源。
  3. 完成第一轮筛选。
  4. 对高风险异常核验。
  5. 判断是否仍存在关键证据缺口。
  6. 达到证据要求后形成结论。
  7. 保留可复核过程。

常用资料 / 审计证据

  • 数据需求说明。
  • 分析规则。
  • 异常清单。
  • 核验样本。
  • 结论和复核记录。

应用场景

发现5笔接口异常后继续追加十多个日志字段，但前3个数据源已经能够证明5笔均已补传且未影响期间。此时应判断新增分析是否仍有审计价值。

完成后应能回答

  • 什么时候应该停止继续深挖？
  • 交叉验证最少需要保留哪些可复核信息？
  • 怎样说明“异常存在，但没有形成财务错报”？
