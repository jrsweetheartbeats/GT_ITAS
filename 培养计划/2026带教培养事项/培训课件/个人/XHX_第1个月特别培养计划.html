W1 · LEARNING 01

财务报表、科目与会计记录

XHX-M1-W1-L01

学习目标

能够理解资产负债表、利润表、现金流量表与会计科目的基本关系，并从交易追到财务报表。

核心内容

  • 资产负债表反映期末资产、负债和所有者权益；利润表反映期间收入、成本费用和利润。
  • 会计科目是业务交易进入财务报表的基础分类，例如应收账款、存货、营业收入、营业成本。
  • 业务单据不是会计凭证，订单、出库单、发票等记录业务事实，会计凭证记录财务影响。
  • 自动凭证可能由系统业务事件或批处理触发；手工凭证由财务人员录入。
  • IT审计通常不要求独立完成复杂会计判断，但必须知道系统异常最终可能落到哪些科目。
  • 理解科目方向和基本借贷关系，有助于判断多记、少记和跨期。

判断与执行步骤

  1. 从一个业务事件开始。
  2. 确认产生了哪些业务单据。
  3. 确认哪个系统触发会计处理。
  4. 识别主要借贷科目。
  5. 追到财务报表项目。
  6. 说明系统错误可能导致什么错报。

常用资料 / 审计证据

  • 业务流程图
  • 业务单据
  • 总账凭证
  • 明细账
  • 科目余额表
  • 财务报表

应用场景

客户发货后ERP自动生成“借：应收账款；贷：营业收入”。如果发货状态被错误提前设置，会同时影响收入和应收。

完成后应能回答

  • 业务单据和会计凭证分别证明什么？
  • 为什么IT审计需要知道受影响科目？
  • 自动凭证与手工凭证的风险点有什么不同？

W1 · LEARNING 02

财务报表认定

XHX-M1-W1-L02

学习目标

能够把发生、完整性、准确性、截止、权利义务和分类列报用于具体项目判断。

核心内容

  • 发生/存在关注账上记录是否真实，例如没有真实发货却确认收入。
  • 完整性关注应记录事项是否全部入账，例如接口漏传导致收入漏记。
  • 准确性关注金额、数量、价格、成本、汇率等是否正确。
  • 截止关注交易是否记录在正确期间。
  • 权利义务关注资产或负债是否真实归属于企业。
  • 分类与列报关注交易是否进入正确科目或报表项目。
  • 系统异常要先分析会造成多记、少记、金额错误还是跨期，再对应认定。

判断与执行步骤

  1. 描述异常事实。
  2. 判断错报方向。
  3. 识别受影响科目。
  4. 对应主要认定。
  5. 判断还需要什么证据。
  6. 连接到财审或IT审计程序。

常用资料 / 审计证据

  • 总账/明细账
  • 期前期后业务单据
  • 系统日志
  • 接口数据
  • 财审风险清单

应用场景

WMS 12月已发货100笔，但5笔未传ERP。主要影响收入完整性；如果1月才补记，还要考虑截止。

完成后应能回答

  • 为什么不能把所有系统问题都写成“准确性”？
  • 完整性与发生有什么本质区别？
  • 一个异常什么时候会同时影响多个认定？

W1 · LEARNING 03

交易循环与系统链路

XHX-M1-W1-L03

学习目标

能够理解收入、采购、存货、资金等常见交易循环，并识别其中的业务系统和财务系统。

核心内容

  • 收入循环通常包括订单、发货/履约、开票、收入确认、应收和回款。
  • 采购循环通常包括采购申请、订单、收货、入库、发票、应付和付款。
  • 存货循环包括入库、调拨、领料、生产、完工、出库和盘点。
  • 资金循环包括付款申请、审批、银行执行、回执和会计记账。
  • 一个流程可能跨CRM、OMS、WMS、MES、ERP、OA、银企直联等多个系统。
  • 原始业务事实往往发生在外围系统，最终财务记录进入ERP/总账。

判断与执行步骤

  1. 选一个业务循环。
  2. 列出主要业务步骤。
  3. 标出每一步系统。
  4. 标出关键数据。
  5. 标出最终会计处理。
  6. 识别接口、自动控制和系统报表。

常用资料 / 审计证据

  • 业务流程图
  • 系统架构图
  • 接口清单
  • 订单/库存/付款明细
  • 总账

应用场景

收入由OMS记录订单，WMS记录发货，ERP自动记账，支付平台记录回款。只看ERP无法完整理解收入链路。

完成后应能回答

  • 为什么外围业务系统也可能进入IT审计范围？
  • 原始业务事实通常在哪里？
  • 系统之间怎样通过接口形成完整交易链？

W1 · LEARNING 04

收入业务与IT审计关注点

XHX-M1-W1-L04

学习目标

能够用收入流程理解ITAC、Interface、IPE和ITGC为什么会影响财务审计。

核心内容

  • 收入确认通常依赖发货、签收、验收等履约事实，而非简单等于开票。
  • 订单数量、价格、折扣、币种、发货日期和确认日期都是关键字段。
  • 自动价格校验、信用控制、自动收入确认可能构成ITAC。
  • WMS→ERP、OMS→ERP等传输构成Interface。
  • 销售明细、未发货订单、应收账龄等可能构成IPE。
  • 访问和变更ITGC影响上述自动控制和数据是否持续可靠。

判断与执行步骤

  1. 确认收入确认政策。
  2. 画收入系统链路。
  3. 确认触发收入的业务状态。
  4. 识别ITAC/Interface/IPE。
  5. 识别相关ITGC。
  6. 说明测试结果可能怎样影响财审。

常用资料 / 审计证据

  • 销售订单
  • 发货/签收
  • ERP收入明细
  • 价格/折扣配置
  • 接口日志
  • 应收账龄

应用场景

ERP根据WMS“已发货”自动确认收入，财审用销售明细做截止选样。需要同时关注发货数据、接口、自动收入确认和销售明细可靠性。

完成后应能回答

  • 收入确认为什么不能只看发票？
  • Interface失败会影响哪个认定？
  • 财审使用销售明细前为什么要做IPE验证？

W1 · LEARNING 05

存货业务与IT审计关注点

XHX-M1-W1-L05

学习目标

能够理解库存数量、库存状态和库存金额可能来自不同系统和计算逻辑。

核心内容

  • WMS通常更接近仓库数量和实物流转，ERP可能同时记录数量和金额。
  • 库存状态可能包括可用、冻结、在途、质检、委外、寄售等。
  • 库存金额依赖采购成本、生产成本或计价方法。
  • 盘点用于验证实物与系统记录。
  • WMS与ERP接口异常可能造成数量或成本差异。
  • 库存报表作为盘点或财审测试依据时，需要验证IPE可靠性。

判断与执行步骤

  1. 确认库存数量源系统。
  2. 确认库存金额来源。
  3. 确认状态字段。
  4. 确认接口。
  5. 确认盘点差异处理。
  6. 将异常映射到存在、完整性和计价。

常用资料 / 审计证据

  • WMS库存明细
  • ERP库存台账
  • 盘点表
  • 成本计算表
  • 接口日志

应用场景

WMS和ERP都显示某物料1,000件，但盘点只有800件。两套系统一致并不能证明存货存在。

完成后应能回答

  • 库存数量和金额为什么可能来自不同逻辑？
  • 系统一致为什么不等于实物存在？
  • 库存异常通常影响哪些财报认定？

W1 · LEARNING 06

IT审计与财务审计的关系

XHX-M1-W1-L06

学习目标

能够说明ITGC、ITAC、Interface和IPE结果为什么会影响财审的控制依赖和实质性程序。

核心内容

  • 财务审计最终目标是对财务报表是否存在重大错报获取合理保证。
  • IT审计关注系统和数据能否可靠支持业务处理和财务报告。
  • ITGC为系统环境提供基础保障。
  • ITAC直接控制业务处理和计算。
  • Interface保证关键数据跨系统传输。
  • IPE保证财审或业务控制使用的系统信息可靠。
  • IT问题不等于财务错报，但可能导致财审降低控制依赖或增加实质性测试。

判断与执行步骤

  1. 明确IT测试结果。
  2. 确定相关业务循环。
  3. 识别科目/认定。
  4. 确认财审是否依赖该控制/数据。
  5. 分析潜在影响。
  6. 提出进一步审计程序。

常用资料 / 审计证据

  • IT审计底稿
  • 财审计划
  • 重大科目/风险
  • 业务数据
  • 补偿控制资料

应用场景

如果ERP用户访问控制无法依赖，但财审计划依赖ERP自动三单匹配，可能需要增加ITAC直接测试或财审实质性程序。

完成后应能回答

  • IT控制缺陷和财务错报有什么区别？
  • IT审计什么时候需要及时和财审沟通？
  • 为什么系统可靠性会影响财审程序范围？

W2 · LEARNING 01

风险、控制目标与控制活动

XHX-M1-W2-L01

学习目标

能够区分风险、控制目标、控制活动和测试程序。

核心内容

  • 风险描述可能发生的错误或未经授权行为。
  • 控制目标描述企业希望达到的状态。
  • 控制活动是企业实际采取的审批、限制、复核等措施。
  • 测试程序是审计人员验证控制是否有效的方法。
  • 同一风险可以由多个控制应对。
  • 程序设计必须能够回到风险解释为什么需要。

判断与执行步骤

  1. 描述风险。
  2. 判断是否影响业务/财务数据。
  3. 形成控制目标。
  4. 了解企业控制活动。
  5. 评价设计。
  6. 设计执行测试。

常用资料 / 审计证据

  • 流程制度
  • 控制矩阵
  • 系统配置
  • 审批记录
  • 系统日志

应用场景

离职用户仍可访问ERP。风险是未经授权访问或修改；控制目标是离职后及时取消访问；停用流程才是控制活动。

完成后应能回答

  • 风险和控制目标有什么区别？
  • 为什么“检查离职账号”不是控制目标？
  • 程序为什么不能直接从截图开始？

W2 · LEARNING 02

设计有效性与执行有效性

XHX-M1-W2-L02

学习目标

能够分别判断控制设计是否合理，以及控制是否在期间内按设计运行。

核心内容

  • 设计有效性关注控制有没有能力预防或发现风险。
  • 执行有效性关注控制实际是否持续执行。
  • 制度存在不代表控制实际运行。
  • 期末截图通常只能证明一个时点。
  • 访谈可以帮助理解，但不能单独证明执行有效。
  • 补偿控制可能改变最终评价。

判断与执行步骤

  1. 明确控制目标。
  2. 了解设计。
  3. 判断设计能否覆盖风险。
  4. 确认控制频率。
  5. 取得期间执行证据。
  6. 调查例外。
  7. 形成设计/执行结论。

常用资料 / 审计证据

  • 制度
  • 配置截图
  • 全年执行记录
  • 审批/日志
  • 补偿控制

应用场景

制度要求离职1天内停用，但实际由IT每月人工清理。即使月底都能关掉，设计本身可能无法满足“及时停用”。

完成后应能回答

  • 设计缺陷和执行偏差有什么区别？
  • 期末截图能证明到哪一步？
  • 访谈为什么不能单独作为执行证据？

W2 · LEARNING 03

总体、期间与样本

XHX-M1-W2-L03

学习目标

能够理解控制测试为什么需要定义总体，并验证总体完整性。

核心内容

  • 总体是审计期间内所有相关控制执行对象。
  • 新增用户总体、离职用户总体、程序变更总体都应覆盖完整期间。
  • 客户挑选的代表性记录不能直接当总体。
  • 总体完整性本身需要系统或独立数据支持。
  • 样本数量与控制频率、风险和方法论相关。
  • 自动控制和人工控制的样本思路不同。

判断与执行步骤

  1. 确定期间。
  2. 定义总体。
  3. 确认总体来源。
  4. 验证完整性。
  5. 确定样本。
  6. 记录样本选择。
  7. 发现例外后决定是否扩大测试。

常用资料 / 审计证据

  • HR清单
  • 账号总体
  • 变更清单
  • 日志/工单
  • 抽样记录

应用场景

客户提供10个“典型程序变更”，但全年实际可能有80个。应先获取全年总体再抽样。

完成后应能回答

  • 为什么客户给的样本不能代替总体？
  • 如何验证总体完整性？

W4 · LEARNING 04

输入输出校验与结果可靠性

XHX-M1-W4-L04

学习目标

能够用基础工程方法验证分析结果没有因为读取、Join、过滤或聚合错误而失真。

核心内容

  • 程序运行成功不代表结果正确。
  • 输入需要检查字段、期间、空值、重复和记录数。
  • Join后应检查记录数是否异常放大。
  • 过滤后应检查数量/金额变化是否合理。
  • 最终异常应可追溯到源记录。
  • 关键结果可以用Excel、第二条SQL或人工样本独立复核。

判断与执行步骤

  1. 记录输入统计。
  2. 检查必需字段。
  3. 执行Join/过滤。
  4. 记录关键节点统计。
  5. 检查输出。
  6. 抽样反向追源。
  7. 独立验证关键结果。

常用资料 / 审计证据

  • 运行统计
  • 源数据
  • 中间结果
  • 异常明细
  • 独立核验表

应用场景

10万订单与9万收入Join后变成40万行，需要先检查一对多关系，而不是继续计算差异金额。

完成后应能回答

  • 程序无报错为什么不代表结果可靠？
  • Join后最先应该看什么？
  • 怎样证明异常结果可以追溯？

W4 · LEARNING 05

异常核验与结论边界

XHX-M1-W4-L05

学习目标

能够把数据规则命中继续核验为可支持审计判断的事实。

核心内容

  • 规则命中只是线索。
  • 需要区分正常业务原因、数据质量、时间差和真实控制/交易异常。
  • 高风险异常应结合业务单据、日志或财务记录核验。
  • 异常数量不等于问题数量。
  • 结论要区分“识别到待核验记录”“确认控制偏差”“发现财务影响”。
  • 证据不足时要明确限制，不直接下强结论。

判断与执行步骤

  1. 保留完整命中总体。
  2. 按风险分层。
  3. 抽取高风险。
  4. 取得补充证据。
  5. 追业务结果。
  6. 追财务结果。
  7. 形成有边界结论。

常用资料 / 审计证据

  • 异常明细
  • 业务单据
  • 系统日志
  • 财务凭证
  • 客户解释+支持资料

应用场景

程序筛出20个离职后登录账号，其中15个是服务账号误映射，5个是真实员工账号。需要继续核验这5个账号的实际操作。

完成后应能回答

  • 异常和问题有什么区别？
  • 什么证据能把“登录”进一步验证到“实际风险”？
  • 怎样写“有异常但没有财务影响”？

W4 · LEARNING 06

底稿表达与项目沟通

XHX-M1-W4-L06

学习目标

核心内容

  • 说明数据来源、总体可靠性和关键口径。
  • 用业务语言说明分析规则。
  • 结果应汇总总体、命中、核验和剩余异常。
  • 结论应说明控制/科目/认定影响以及限制。

  2. 写数据来源。
  3. 写口径和规则。

  5. 写异常核验。
  6. 写结论/限制。
