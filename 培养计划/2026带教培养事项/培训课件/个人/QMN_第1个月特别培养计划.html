W1 · LEARNING 01

一笔业务如何进入财务报表

QMN-M1-W1-L01

学习目标

能够从业务事件开始，说明系统如何处理并最终形成会计记录和财务报表项目。

核心内容

  • 业务从订单、发货、收货、付款等真实事件开始。
  • 系统负责记录和处理业务数据。
  • 部分系统会自动生成会计凭证，部分由财务手工记账。
  • 会计科目把交易分类进入资产、负债、收入、成本费用等报表项目。
  • IT审计关注系统和数据是否可靠支持这些处理。
  • 理解业务到财报的链路，是后续理解ITGC、ITAC和IPE的基础。

判断与执行步骤

  1. 选择一笔真实交易。
  2. 列出业务步骤。
  3. 标出系统。
  4. 找到会计处理触发点。
  5. 识别主要科目。
  6. 说明系统错误可能造成什么财务影响。

常用资料 / 审计证据

  • 业务流程图
  • 订单/收货/付款等业务单据
  • 系统截图
  • 会计凭证
  • 明细账/总账

应用场景

客户订单在销售系统生成，发货后ERP自动生成收入凭证。需要知道订单、发货和凭证分别代表什么事实。

完成后应能回答

  • 业务单据和会计凭证有什么区别？
  • 为什么IT审计需要知道受影响科目？
  • 系统错误怎样传导到财务报表？

W1 · LEARNING 02

财务报表认定

QMN-M1-W1-L02

学习目标

能够理解发生、完整性、准确性、截止等认定，并用于简单案例。

核心内容

  • 发生/存在关注账面记录是否真实。
  • 完整性关注应记录事项是否全部记录。
  • 准确性关注金额、数量、价格等是否正确。
  • 截止关注是否记录在正确期间。
  • 权利义务关注资产负债是否真实归属企业。
  • 分类列报关注是否进入正确科目和报表项目。

判断与执行步骤

  1. 先描述异常。
  2. 判断多记/少记/金额错误/跨期。
  3. 识别科目。
  4. 对应认定。
  5. 判断需要什么证据。
  6. 连接到审计程序。

常用资料 / 审计证据

  • 总账
  • 明细账
  • 业务单据
  • 系统/接口数据
  • 财审风险清单

应用场景

WMS已经发货，但5笔订单没有进入ERP收入。主要影响收入完整性；如果跨年还涉及截止。

完成后应能回答

  • 发生和完整性怎么区分？
  • 为什么一个异常可能影响多个认定？
  • 认定如何帮助确定测试方向？

W1 · LEARNING 03

ITGC是什么

QMN-M1-W1-L03

学习目标

能够理解ITGC是支持系统持续可靠运行的基础控制，而不是一组孤立检查点。

核心内容

  • ITGC常见领域包括访问管理、程序变更、运维和备份。
  • 访问控制关注谁可以进入系统、拥有何种权限。
  • 变更控制关注谁可以修改程序和配置、是否经过测试和审批。
  • 运维关注作业、日志、异常和事件处理。
  • 备份恢复关注故障后数据和系统能否恢复。
  • ITGC通常为ITAC、Interface和IPE的可靠性提供基础。

判断与执行步骤

  1. 确认系统是否重要。
  2. 识别IT风险。
  3. 形成控制目标。
  4. 了解企业控制。
  5. 取得证据。
  6. 评价设计和执行。

常用资料 / 审计证据

  • IT制度
  • 账号/权限
  • 变更工单
  • 日志
  • 备份记录

应用场景

ERP自动控制看起来运行正常，但IT管理员可直接修改生产程序且没有日志。需要考虑基础ITGC是否影响控制可靠性。

完成后应能回答

  • ITGC主要解决什么问题？
  • 为什么ITGC会影响ITAC？
  • ITGC问题是否等于财务报表一定错？

W1 · LEARNING 04

ITAC是什么

QMN-M1-W1-L04

学习目标

能够识别简单自动计算、自动限制、自动审批和自动匹配。

核心内容

  • ITAC是应用系统自动执行或高度依赖系统逻辑的业务控制。
  • 自动审批可按金额或业务类型自动决定审批路径。
  • 系统限制可阻止超信用额度、冻结供应商等交易。
  • 自动计算可执行成本、折旧、税额等计算。
  • 自动匹配可实现采购订单、入库和发票三单匹配。
  • ITAC测试需要理解风险、配置、输入、处理和输出。

判断与执行步骤

  1. 先明确业务风险。
  2. 确认控制触发条件。
  3. 识别参数和输入。
  4. 理解系统处理。
  5. 确认输出/例外。
  6. 判断财审为何依赖。

常用资料 / 审计证据

  • 系统配置
  • 主数据
  • 业务样本
  • 审批轨迹
  • 异常清单

应用场景

系统规定100万元以上付款自动进入CFO审批。该流程属于自动工作流ITAC。

完成后应能回答

  • 系统有自动功能就一定是ITAC吗？
  • ITAC为什么要连接业务风险？
  • ITAC需要关注哪些输入和参数？

W1 · LEARNING 05

Interface与IPE是什么

QMN-M1-W1-L05

学习目标

能够区分系统间数据传输和系统生成信息，并理解二者的审计目的。

核心内容

  • Interface是系统之间的数据传输。
  • 源系统、目标系统、关键字段、传输频率和失败处理是Interface核心。
  • IPE是审计或业务控制使用的系统生成信息。
  • 销售明细、库存报表、应收账龄可能属于IPE。
  • Interface重点验证完整性和准确性。
  • IPE重点验证来源、参数、总体、字段和导出后处理。

判断与执行步骤

  1. 先判断对象是“传输”还是“报表”。
  2. 确认业务用途。
  3. 确认系统来源。
  4. 确认关键数据。
  5. 设计完整性/准确性验证。
  6. 判断ITGC依赖。

常用资料 / 审计证据

  • 接口Mapping
  • 接口日志
  • 源/目标明细
  • 系统报表
  • 查询参数

应用场景

WMS把发货传ERP属于Interface；财审使用ERP销售明细做选样，这份销售明细属于IPE。

完成后应能回答

  • Interface与IPE最核心的区别是什么？
  • 为什么一份报表不能只看总额？
  • Interface失败会如何影响财务数据？

W1 · LEARNING 06

CAATs在IT审计中的位置

QMN-M1-W1-L06

学习目标

能够理解数据分析是审计程序的一种执行方式，需要先有明确审计问题。

核心内容

  • CAATs可用于总体核对、权限分析、日志分析、接口核对、交易异常识别。
  • 工具可以是Excel、SQL、Python等，工具不是审计目标。
  • 分析前需要明确业务口径、总体、字段和规则。
  • 规则命中只是异常线索，不自动等于问题。
  • 关键异常需要回到业务、系统或财务证据继续核验。
  • 第一阶段优先学审计逻辑，不追求复杂算法。

判断与执行步骤

  1. 明确审计问题。
  2. 定义总体。
  3. 定义业务口径。
  4. 设计规则。
  5. 选择工具。
  6. 核验异常。
  7. 形成结论。

常用资料 / 审计证据

  • 审计程序
  • 数据字典
  • 业务数据
  • 异常明细
  • 核验证据

应用场景

用SQL筛出离职后仍Active账号，只是找到了待核验记录；还需要结合登录和操作日志判断实际风险。

完成后应能回答

  • 为什么不能拿到数据就直接分析？
  • 规则命中和审计问题有什么区别？
  • 什么时候数据分析结果可以进入底稿结论？

W2 · LEARNING 01

风险、控制目标与测试程序

QMN-M1-W2-L01

学习目标

能够区分风险、控制目标、企业控制和审计程序。

核心内容

  • 风险描述可能发生的错误或未经授权行为。
  • 控制目标描述企业希望达到的状态。
  • 控制活动是企业实际采取的措施。
  • 审计程序用于验证控制设计和执行。
  • 不能把“检查截图”写成控制目标。
  • 每一步程序都要能解释为什么做。

判断与执行步骤

  1. 写风险。
  2. 写控制目标。
  3. 了解企业控制。
  4. 评价设计。
  5. 写测试步骤。
  6. 列预期证据。

常用资料 / 审计证据

  • 制度
  • 流程图
  • 系统配置
  • 审批记录
  • 日志

应用场景

离职账号晚停用的风险是离职人员继续访问，而控制目标是及时取消访问权限。

完成后应能回答

  • 风险和控制目标有什么区别？
  • 测试程序为什么不能从截图开始？
  • 怎样判断一条程序有没有明确目的？

W2 · LEARNING 02

控制设计与执行

QMN-M1-W2-L02

学习目标

能够区分“控制设计得好不好”和“期间有没有按设计执行”。

核心内容

  • 设计有效性关注控制本身是否能应对风险。
  • 执行有效性关注控制是否持续运行。
  • 制度存在不等于实际执行。
  • 当前配置截图不代表全年有效。
  • 访谈可以帮助理解，但不能单独证明执行。
  • 异常后要判断是设计问题还是执行问题。

判断与执行步骤

  1. 明确控制目标。
  2. 了解控制设计。
  3. 评价设计。
  4. 确定频率。
  5. 取得期间执行证据。
  6. 处理例外。

常用资料 / 审计证据

  • 制度
  • 配置
  • 全年记录
  • 审批/日志
  • 访谈纪要

应用场景

制度要求离职1天内停用，但IT只每月清理一次。即使月底都关掉，设计也可能不足。

完成后应能回答

  • 设计缺陷和执行偏差怎么区分？
  • 一张截图能支持什么结论？
  • 访谈为什么不能替代执行证据？

W2 · LEARNING 03

总体、期间与样本

QMN-M1-W2-L03

学习目标

能够理解测试为什么需要总体和样本。

核心内容

  • 总体是审计期间所有相关控制对象。
  • 用户访问测试可能需要全年新增、变更、离职总体。
  • 变更测试需要全年程序变更总体。
  • 客户挑选的样本不能代表总体。
  • 总体完整性需要额外验证。
  • 样本数量与控制频率和方法论有关。

判断与执行步骤

  1. 确定期间。
  2. 定义总体。
  3. 确认总体来源。
  4. 验证完整性。
  5. 选择样本。
  6. 记录抽样依据。

常用资料 / 审计证据

  • HR清单
  • 账号总体
  • 变更清单
  • 系统日志
  • 抽样记录

应用场景

客户只提供10个变更样本，但没有全年变更清单。应先补总体。

完成后应能回答

  • 总体为什么重要？
  • 怎样验证总体完整？
  • 什么时候客户提供的样本不能直接使用？

W2 · LEARNING 04

证据判断基础

QMN-M1-W2-L04

学习目标

能够判断截图、日志、制度、审批等证据各自能证明什么。

核心内容

  • 截图通常证明某个时点的状态。
  • 日志更适合证明历史事件。
  • 制度证明控制要求，不证明实际执行。
  • 审批记录证明授权。
  • 客户解释帮助理解，但需其他证据支持关键结论。
  • 证据不足时要明确缺口。

判断与执行步骤

  1. 先写待证明事项。
  2. 列现有证据。
  3. 判断各自证明力。
  4. 检查期间。
  5. 识别缺口。
  6. 补取替代证据。

常用资料 / 审计证据

  • 系统截图
  • 日志
  • 制度
  • 审批
  • 业务资料

应用场景

当前截图显示账号已停用，但无法看到停用时间，只能证明当前状态。

完成后应能回答

  • “有证据”和“证据够”有什么区别？
  • 什么时候必须取得日志？
  • 资料不足时怎么写结论？

W2 · LEARNING 05

用户访问管理

QMN-M1-W2-L05

学习目标

能够完成新增、离职和高权限的基础测试。

核心内容

  • 新增账号需要适当授权。
  • 权限应符合岗位职责。
  • 离职账号应及时停用。
  • 高权限需要限制和增强责任追踪。
  • 共享账号需要理解实际使用和补偿控制。
  • 异常后可继续检查登录和操作日志。

判断与执行步骤

  1. 获取HR和账号总体。
  2. 匹配人员与账号。
  3. 抽样新增/离职。
  4. 核对审批和实际权限。
  5. 检查高权限。
  6. 调查异常。

常用资料 / 审计证据

  • HR
  • 账号清单
  • 角色权限
  • 审批
  • 登录/操作日志

应用场景

员工3月1日离职，账号3月8日停用且期间无登录。存在执行偏差，但未发现实际使用。

完成后应能回答
